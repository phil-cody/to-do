# Данные, версии и совместимость

## Где находятся данные

| Режим                 | Основное хранилище                   | Дополнительное хранилище                     |
| --------------------- | ------------------------------------ | -------------------------------------------- |
| Локальный dev/preview | localStorage, ключ todo_app          | Другие вкладки получают событие storage      |
| Серверный             | SQLite, снимок по Telegram ID        | IndexedDB: кеш и устойчивая очередь аккаунта |
| Резервная копия       | JSON-файл на устройстве пользователя | Не заменяет резервную копию всей SQLite-базы |

Origin включает протокол, хост и порт. localhost:4000, localhost:4002 и HTTPS-домен с :8443 имеют разные localStorage, IndexedDB и сессии. Смена адреса требует явного [переноса через файл](import.md).

## Разные версии

| Обозначение            | Текущее значение          | Что означает                               |
| ---------------------- | ------------------------- | ------------------------------------------ |
| schemaVersion          | 2                         | Формат снимка рабочей области              |
| format/version шаблона | just-to-do-it/project / 1 | Формат подготовленного проекта для импорта |
| PRAGMA user_version    | 1                         | Схема серверной SQLite-базы                |
| REVISION               | Полный SHA Git            | Код установленного релиза, не версия задач |

Не изменяйте эти значения, чтобы выдать старый файл или архив за новый.

## Снимок рабочей области

| Объект    | Поля                                                                                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace | schemaVersion, projects, selectedProjectId (ID проекта или all), allView, allFilter                                                                                     |
| Project   | project_id, project_title, project_description, project_priority, project_pinned, project_pin_position, project_type, project_view, project_filter, createdAt, todoList |
| Task      | task_id, task_project, task_title, task_description, task_due_date, task_status, task_priority, task_createdAt                                                          |

Статусы: pending, in-process, completed. Приоритеты: high, medium, low. Виды: grid, list, kanban. Срок — существующая календарная дата ГГГГ-ММ-ДД или пустая строка. Новые объекты получают ID через crypto.randomUUID() и ISO-время создания; у старых объектов время может отсутствовать или быть пустым.

Пример внутреннего снимка с одной задачей:

```json
{
  "schemaVersion": 2,
  "selectedProjectId": "inbox-example",
  "allView": "list",
  "allFilter": "all",
  "projects": [
    {
      "project_id": "inbox-example",
      "project_title": "Inbox",
      "project_description": "",
      "project_priority": 1,
      "project_pinned": true,
      "project_pin_position": 0,
      "project_type": "inbox",
      "project_view": "grid",
      "project_filter": "all",
      "createdAt": "",
      "todoList": [
        {
          "task_id": "task-example",
          "task_project": "inbox-example",
          "task_title": "Подготовить план",
          "task_description": "**Первый шаг**",
          "task_due_date": "",
          "task_status": "pending",
          "task_priority": "low",
          "task_createdAt": ""
        }
      ]
    }
  ]
}
```

Для подготовки нового проекта используйте [читаемый шаблон](templates/README.md), а не назначайте внутренние ID вручную. Полный снимок также принимается импортом, но его ID не переносятся в текущую рабочую область.

## Общие ограничения

Источник ограничений — workspaceLimits в src/app/model.js. Его используют импорт, редактор и сервер. Статусы, приоритеты, виды и календарная проверка isDueDate также определены в общей модели.

| Ограничение                            | Значение                            |
| -------------------------------------- | ----------------------------------- |
| Проекты                                | 300 на рабочую область              |
| Задачи                                 | 10000 суммарно                      |
| Название                               | 200 символов JavaScript (UTF-16)    |
| Одно описание                          | 100000 символов JavaScript (UTF-16) |
| project_priority                       | Целое число 1–999999                |
| Итоговый снимок без содержимого файлов | 2000000 байт UTF-8                  |
| Тело HTTP-запроса                      | 2097152 байта (2 МиБ)               |

Лимит снимка применяется после приведения сервером к известным полям, включая добавление задач ботом. HTTP-лимит чуть больше, чтобы оставить место для передачи снимка. Превышение не обрезает текст: запись отклоняется. Локальные правки вне импорта ограничиваются возможностями браузерного хранилища; серверные проверки выполняются только при сохранении на сервере.

## Нормализация, импорт и серверная проверка

Это разные операции:

- model.normalize() загружает старое локальное состояние, сохраняет ID и дополнительные поля проектов/задач, исправляет task_project по родительскому todoList, дополняет настройки. Пустой список становится Inbox. Повторяющиеся ID или неверная структура вызывают ошибку; исходное хранилище не перезаписывается.
- parseProjectImport() проверяет шаблон или резервную копию и копирует только известные поля в предпросмотр. Неизвестные поля нового шаблона считаются ошибкой; дополнительные поля старой копии не переносятся. appendProjectImport() создаёт новые ID, разрешает совпадение названий и проверяет общий объём до сохранения.
- validateSnapshot() строго проверяет входящий серверный снимок, принадлежность задач, ID, значения и лимиты. В SQLite сохраняются только объявленные поля. Нормализация сама по себе не является серверной проверкой.

Совместимость описаний обрабатывает description.normalizeDescription(). Старый однострочный список `- План [x] - Десктоп [ ] - Адаптивность` превращается в три строки Markdown; fenced, indented и inline-код сохраняется. Отдельное пересохранение каждой задачи не требуется. Это ограниченное преобразование старого формата, а не универсальное исправление Markdown.

## Порядок и закрепление

Закреплённые проекты идут первыми по project_pin_position; новое закрепление добавляется в конец группы. Отрицательные старые позиции допустимы. Незакреплённые сортируются по project_priority; название разрешает равенство ключей. Повторное закрепление добавляет проект в конец закреплённых.

Группы задач: просроченные → в работе → ожидающие → завершённые. Просрочка вычисляется из срока раньше сегодняшней локальной даты и незавершённого статуса. Внутри группы: срок по возрастанию (без срока в конце), высокий → средний → низкий приоритет, название по алфавиту выбранного языка без учёта регистра, время создания, ID. Производная сортировка не меняет сохранённый массив. Смена локального дня обновляет представление без перезагрузки.

## Язык

Язык аккаунта хранится в users.settings.language: только en или ru. Это настройка аккаунта, а не поле проекта, задачи или импортируемого JSON. Старые записи без language читаются как ru; изменение языка дополняет JSON настроек без миграции схемы SQLite и без сброса enabled/time/timezone. У новых аккаунтов учитывается language_code Telegram; если он отсутствует, используется ru, остальные языки отображаются как en.

В браузере todo_language хранит выбор локального интерфейса. В серверном режиме подтверждённый язык аккаунта имеет приоритет и дополнительно записывается рядом со снимком/очередью IndexedDB для офлайн-перезагрузки. JSON-экспорт проектов не переносит настройку аккаунта; полная копия SQLite её содержит. Состояние аккордеона описания хранится только в React.

## Сохранение и копии

В серверном режиме selectedProjectId хранится отдельно от синхронизируемого снимка: это локальное поле записи user:<Telegram ID> в IndexedDB. pendingSnapshot накладывает его после применения очереди. Оно не участвует в mergeEdit и не создаёт серверной операции. Устройства выбирают проекты независимо; вкладки одного профиля браузера разделяют локальный выбор. При удалении выбранного проекта отображается all. В прежнем снимке и JSON-экспорте поле остаётся для совместимости; в локальном режиме оно по-прежнему входит в todo_app.

Подтверждённый снимок меняется после успешной записи. Быстрые действия имеют отдельное временное представление в интерфейсе: при отказе записи оно удаляется, при успехе заменяется сохранёнными данными. Формы не закрываются до подтверждения, ошибка сохраняет черновик. При одновременных локальных записях действует последняя запись. Серверный режим сначала сохраняет правку в очередь IndexedDB, затем применяет ревизии, ID операций и объединение полей. Ошибка связи или ответ 5xx сохраняет очередь для повторной отправки; явный отказ записи (кроме конфликта и истечения сессии) удаляет только отвергнутую операцию и публикует восстановленный снимок. Конфликт требует решения пользователя; детали — в [server.md](server.md).

«Скачать текущие задачи» и «Скачать резервную копию» формируют JSON локально. Для серверного аккаунта экспорт учитывает неотправленные правки. Файл содержит личные данные и не должен попадать в Git или публичную папку. Импорт добавляет копии, а не восстанавливает исходные серверные сессии или ревизии.

## Вложения задач

Необязательное поле `task_attachments` содержит до 10 записей `{id, name, size}`: SHA-256 содержимого в hex, исходное имя (до 255 символов), размер в байтах. Каждый файл — до 20 МиБ, суммарно по ссылкам рабочей области — до 200 МиБ. Старые снимки без этого поля совместимы; `schemaVersion` остаётся 2.

Содержимое хранится отдельно от снимка: в IndexedDB под ключом `attachment:local:<SHA>` или `attachment:user:<account ID>:<SHA>`, на сервере — в таблице SQLite `attachments`. Таблица добавляется через `CREATE TABLE IF NOT EXISTS`, без изменения прежних таблиц и `user_version`. Резервная копия всей SQLite включает файлы. Для отката сначала сохраните копию новой базы: старый код может отбросить неизвестные ссылки при записи снимка; файлы останутся в дополнительной таблице, но старая версия их не показывает.

При сохранении файла клиент сначала записывает байты в IndexedDB, затем сохраняет снимок с метаданными. В серверном режиме перед отправкой операции загружаются новые файлы. Повторная загрузка одинакового содержимого идемпотентна и проверяет SHA-256. Офлайн-правки переживают перезагрузку; на другом устройстве файл доступен после загрузки на сервер и сохранения операции. Просмотренные/скачанные файлы кешируются в IndexedDB; ещё не полученный файл офлайн недоступен. Удаление вложения удаляет ссылку в задаче. Сервер удаляет файлы старше семи дней, когда на них не ссылается текущий снимок; до очистки допускается до 400 МиБ физических файлов на аккаунт. Локальный кеш автоматически не очищается.

JSON-экспорт добавляет поле `data` с base64 к каждому вложению. Если какой-либо файл недоступен, экспорт завершается ошибкой, а не неполной копией. Импорт проверяет структуру, размер и SHA-256 перед сохранением; содержимое отделяется от снимка и сохраняется под текущим аккаунтом. Копия JSON ограничена 285 МиБ, а очищенный снимок по-прежнему 2000000 байт. Большие копии требуют соответствующей свободной памяти браузера и места в IndexedDB. Файлы не попадают в Cache Storage и не отображаются как исполняемый контент: скачиваются с типом `application/octet-stream`.

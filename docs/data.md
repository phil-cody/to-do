# Данные и совместимость

В локальном режиме снимок хранится в localStorage под ключом `todo_app`. В серверном — в SQLite по владельцу Telegram ID; IndexedDB хранит кеш и очередь этого аккаунта. Формат — JSON, текущая версия `schemaVersion: 2`. Образец полного снимка и API приведены в [контракте хранения](server.md).

## Поля

| Объект    | Поля и значения                                                                                                                                                                               |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace | `projects`, `selectedProjectId` (ID проекта или `all`), `allView`, `allFilter`, `schemaVersion`                                                                                               |
| Project   | `project_id`, `project_title`, `project_description`, `project_priority`, `project_pinned`, `project_pin_position`, `project_type`, `project_view`, `project_filter`, `createdAt`, `todoList` |
| Task      | `task_id`, `task_project`, `task_title`, `task_description`, `task_due_date`, `task_status`, `task_priority`, `task_createdAt`                                                                |

Статусы задач: `pending`, `in-process`, `completed`. Приоритеты: `high`, `medium`, `low`. Виды: `grid`, `list`, `kanban`. Срок — календарная дата `YYYY-MM-DD` или пустая строка; время создания новых объектов — ISO timestamp. ID новых объектов создаёт `crypto.randomUUID()`.

Проектный приоритет — положительное число порядка, меньшие числа идут раньше среди незакреплённых. `project_pin_position` — целый ключ позиции внутри закреплённых; новое закрепление получает ключ больше существующих. Отрицательные ключи из старых снимков допустимы.

## Загрузка старого снимка

`model.normalize()` сохраняет существующие ID и дополнительные поля проектов/задач, исправляет принадлежность задачи по её родительскому `todoList`, дополняет отсутствующие настройки. Если проектов нет, создаётся Inbox. Некорректная структура списка и повторяющиеся ID вызывают ошибку; исходная строка хранилища не перезаписывается. Прочие неизвестные значения статуса/приоритета получают безопасные значения по умолчанию.

`description.normalizeDescription()` переводит старые однострочные чек-листы в обычный Markdown:

```text
- План [x] - Десктоп [ ] - Адаптивность
```

превращается в:

```markdown
- План
- [x] Десктоп
- [ ] Адаптивность
```

Преобразование происходит при загрузке, поэтому отдельное пересохранение задач не требуется. Код в fenced, indented и inline блоках сохраняется. Нормализация — слой совместимости, а не универсальное восстановление любого некорректного Markdown.

## Сортировка

Закреплённые проекты идут первыми, по `project_pin_position`. Незакреплённые — по `project_priority`; название разрешает равенство ключей. Отмена закрепления возвращает проект в обычную группу, повторное закрепление добавляет в конец закреплённых.

Задачи сортируются по группам: Overdue → In process → Pending → Completed. Overdue вычисляется из срока раньше сегодняшней локальной даты и незавершённого статуса. Внутри группы: срок по возрастанию (без срока — в конце), High → Medium → Low, время создания, ID. Сортировка не меняет сохранённый массив. Смена локального дня обновляет представление без перезагрузки.

## Сохранение и резервные копии

Сохраняется весь снимок, включая настройки вида. Локальные вкладки обновляются по событию storage; при одновременной записи локального режима остаётся правило последней записи. Серверный режим использует ревизию, ID операции, очередь IndexedDB и объединение правок по полям. Пересечение правок требует выбора пользователя; детали — в [server.md](server.md).

localStorage принадлежит origin: протоколу, хосту и порту. Обновление файлов на прежнем домене сохраняет данные; смена домена, HTTP/HTTPS, localhost/127.0.0.1 или порта требует ручного переноса. [Статическая инструкция](vps-static.md) содержит экспорт и восстановление. Перенос в аккаунт выполняется явно через раздел «Telegram и аккаунт».

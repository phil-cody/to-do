# Устройство приложения

React-интерфейс работает с асинхронным адаптером хранения. В локальном режиме используется localStorage; в серверном — SQLite, Telegram-сессия, очередь IndexedDB и синхронизация через API.

## Изменение данных

`App` соединяет представления, а `useWorkspace` передаёт им callbacks. Чистые функции `workspace.js` и `model.js` создают новый снимок без изменения исходного объекта. Производные данные, поиск и эффективный вид вычисляет `selectDashboard()`.

В локальном режиме `commit` публикует снимок после записи в localStorage; неудачная запись оставляет прежние данные и открытый редактор. В серверном режиме надёжная запись сначала означает фиксацию правки в IndexedDB, затем отправку. Если сеть недоступна, интерфейс показывает очередь. При конфликте локальный черновик сохраняется до решения пользователя.

Сервер проверяет сессию и владельца, валидирует снимок и сохраняет его вместе с новой ревизией и ID операции одной транзакцией SQLite. SSE сообщает подключённым браузерам номер ревизии. Никакой Telegram ID из тела запроса не выбирает владельца данных.

## Вход и фоновые задачи

Бот получает updates напрямую от Telegram через long polling. Запрос входа привязан к секретной cookie исходного браузера, Telegram ID подтверждается личным callback боту. Сервер выдаёт случайную cookie-сессию; хеш хранится в SQLite.

Сообщения Inbox и отметки обработанных updates записываются транзакцией. Исходящие сообщения — в постоянной очереди; планировщик создаёт один выпуск за локальный день в часовом поясе пользователя. Сеть Telegram не вызывается внутри SQL-транзакций.

## Интерфейс и стили

Формы используют отдельный черновик. `WorkspaceModal` выбирает форму, подробности или dashboard проектов. Native dialog управляет модальным фокусом, drawer блокирует прокрутку. `SyncPanel` показывает состояние сети, конфликты, настройки бота и действия аккаунта.

Markdown и редактор загружаются отдельным модулем. Санитизация действует в карточке, Show more и предпросмотре. Внешние изображения заменены ссылками. Стили в `styles/` сгруппированы по частям интерфейса; media queries подключаются последними.

## Сборка и офлайн

Webpack создаёт `dist/` с хешированными файлами, CSP и `sw.js`. Разработка использует отдельную `.cache/dev/`. Service worker кеширует все необходимые модули публичной оболочки; API исключён из кеша. Личные данные находятся в IndexedDB своего аккаунта.

Backend добавляет `/api/workspace` в meta-конфигурацию выдаваемого HTML. Поэтому одна и та же статическая сборка может работать локально без API или через Node-сервер с аккаунтами. На VPS Nginx проксирует к Node; база и секреты находятся за пределами dist.

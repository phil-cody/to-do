# Разработка и проверки

## Первый запуск

Рекомендуется Node.js 24 LTS (`.nvmrc`); минимальный runtime — Node.js 24. Проверенная среда: Node 24.15.0, npm 11.12.1.

```sh
nvm use                 # если установлен nvm
npm ci
npm run dev
```

Откройте `http://localhost:4000`. Если там уже есть задачи, используйте **тот же адрес и профиль браузера**. Перед изменением старых данных сделайте [резервную копию](vps-static.md#1-проверка-на-своих-данных-до-публикации).

## Команды

| Команда                                  | Назначение                                                |
| ---------------------------------------- | --------------------------------------------------------- |
| `npm run dev`                            | Сервер разработки и автоматическая пересборка на 4000     |
| `npm start`, `npm run watch`             | Алиасы запуска dev                                        |
| `npm run build`                          | Production-сборка в dist                                  |
| `npm run prod`                           | Алиас production-сборки                                   |
| `npm run build:dev`                      | Разовая dev-сборка в dist; для деплоя не использовать     |
| `npm run server`                         | Сервер, SQLite и Telegram на 4001 (настройки в .env)      |
| `npm run preview`                        | Просмотр уже собранного dist на 4002                      |
| `npm test`                               | Модульные проверки модели, адаптеров и действий           |
| `npm run test:e2e`                       | Сценарии браузера, размеры, безопасность и production CSP |
| `npm run format`, `npm run format:check` | Применение / проверка единого форматирования              |
| `npm run test:visual -- capture`         | Эталон геометрии и стилей в .cache                        |
| `npm run test:visual -- compare`         | Сравнение с локальным эталоном                            |

Перед первым браузерным тестом выполните `npx playwright install chromium`. Playwright автоматически запускает отдельный dev-сервер на 4012, свежую production-сборку с preview на 4013 и тестовый backend. Их процессы всегда создаются заново; открытые серверы на 4000/4002 не используются. У dev-серверов раздельные каталоги сборки в `.cache/dev-ПОРТ`. Backend-стенд использует имитацию Telegram на портах 4010/4011 и память вместо пользовательской базы; его нельзя публиковать на VPS. Серверные HTTP-тесты дополнительно используют порт 4018. Все данные тестов синтетические, профили изолированы от пользовательского браузера.

Визуальное сравнение требует запущенного dev-сервера. Снимок включает 360, 399, 636, 760 и 1440 px, List/Grid/Kanban и форму. Эталон создайте **до** изменения, сравнивайте в той же среде. Этот инструмент дополняет браузерные проверки; он не заменяет ручной просмотр длинных описаний и всех вариантов контента.

## Куда вносить изменения

- Новое действие с данными: `workspace.js` или `model.js`, затем callback в `useWorkspace.js`.
- Данные для отображения и поиск: `selectors.js`; не сохраняйте производные поля в snapshot.
- Новый способ хранения: `repository.js`, общий async-контракт `load/save`.
- Описание Markdown: `description.js` для совместимости, `markdown.jsx` для политики контента, `components/Markdown.jsx` для отображения.
- Поля редактирования: `EditorForm.jsx`, общий диалог — `WorkspaceModal.jsx`.
- Адаптивность и размеры: `styles/`, `app.css`, `constants.js` и `layout.spec.js`.

Не меняйте напрямую данные из props. Сохранение должно пройти через `commit`, чтобы ошибка записи не теряла черновик или предыдущее состояние. Не возвращайте DOM-обработчики старой реализации и не обращайтесь к localStorage из карточек.

Для серверного режима: скопируйте .env.example в .env, задайте токен, выполните npm run build и npm run server. Настройки бота описаны в [telegram.md](telegram.md), протокол — в [server.md](server.md).

## Подготовка релиза

После коммита и push: `npm run release:prepare` → `npm run release:upload` → `npm run release:install`. Все команды выполняются на Mac из папки проекта; две последние используют SSH-псевдоним todo-vps (другой передаётся через `-- my-vps`). Подготовка требует чистого Git и совпадения HEAD с актуальным origin/main, собирает точный коммит и сохраняет архив в `.cache/releases/SHA/`. Передача и установка отвергают старый или повреждённый архив. Подробности и первый запуск — в [инструкции VPS](vps.md).

## Перед выпуском

Перед `npm ci` остановите работающий `npm run dev`: переустановка удаляет node_modules, и старый процесс Webpack может сохранить ошибку разрешения модулей. После установки запустите dev заново; localStorage при этом сохраняется. Тестовые серверы запускаются независимо.

```sh
npm ci
npm run format:check
npm test
npm run test:e2e
npm audit
npm run build
```

Проверки размеров охватывают диапазон 360–1440 px и границы 398/399 и 759/760. Сборка может предупреждать о размере модулей Markdown: редактор загружается отдельно, предупреждение не означает ошибку сборки. Production не включает исходные карты и dev-клиент.

## Диагностика

| Симптом                      | Проверка                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------- |
| «Пропали» задачи             | Сравните протокол/хост/порт и профиль браузера; не очищайте хранилище        |
| Ошибка загрузки              | Проверьте структуру резервной копии; некорректный JSON не перезаписывается   |
| Ошибка сохранения            | Квота/доступ к localStorage или HTTP-ответ; форма должна сохранить черновик  |
| Порт занят                   | Остановите предыдущий dev/preview; сервер слушает только 127.0.0.1           |
| CSP-тест падает              | Проверьте свежесть dist и отсутствие dev-сборки; изучите браузерный отчёт    |
| Задача не выходит из Overdue | Измените срок либо завершите задачу; смена Pending/In process не меняет дату |
| Новый домен пустой           | Восстановите backup на окончательном HTTPS-origin                            |

Отчёты Playwright находятся в `test-results/`, визуальные снимки — в `.cache/`. Эти каталоги не входят в Git или деплой.

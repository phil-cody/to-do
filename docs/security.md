# Безопасность и границы проверки

Локальные проверки охватывают клиент, backend, Telegram-обработчики, импорт, подготовку релизов и браузерные сценарии на синтетических данных. Это описание реализованных мер и границ проверки, а не гарантия отсутствия уязвимостей. Реальная конфигурация VPS, DNS, TLS и доступа к боту проверяется отдельно.

## Результат проверки 15.10.2026

Исправлен риск переноса офлайн-очереди между аккаунтами: ранее при смене общей cookie в другой вкладке старая вкладка могла объединить свой черновик с ответом нового аккаунта. Теперь клиент проверяет владельца ответа, а сервер сверяет X-Account-ID с сессией до выдачи данных или выполнения действия. Сохранение без привязки к аккаунту отклоняется даже для старых клиентов. Проверки охватывают смену аккаунта до обновления и между чтением и записью; очередь сохраняется под прежним ID и не отправляется новому владельцу.

Свежий npm audit: 0 известных уязвимостей для установленного дерева зависимостей. Проверены 110 текущих файлов и 384 исторических Git-объекта с содержимым: шаблоны Telegram/GitHub/AWS-токенов и приватных ключей не обнаружены. В отслеживаемых файлах нет .env с секретами, SQLite, PEM и файлов резервных копий. Это поиск известных форматов, а не доказательство отсутствия любого произвольного секрета. Локального .env во время проверки не было; рабочие настройки VPS и реальные токены не читались.

Также устранена обработка специальных ID вроде **proto** как свойств прототипа: словари проектов и задач при слиянии теперь не имеют прототипа. До исправления такой ID мог потерять запись или вызвать ложный конфликт. Регрессионный тест воспроизвёл ошибку до изменения и проверяет сохранность объектов после него. Признаков чтения чужих аккаунтов через этот дефект не найдено.

Production-сборка проверена отдельно: 11 файлов, без совпадений с указанными форматами секретов, source maps, .env, SQLite и файлов backup. Браузерные проверки подтверждают отсутствие автоматической загрузки внешних Markdown-изображений, работу CSP и отсутствие API-ответов в Cache Storage.

Проверки завершились успешно: 43 модульных теста и полный набор из 66 браузерных сценариев. После последнего исправления слияния повторно прошли все 15 сценариев безопасности и серверной синхронизации с новой production-сборкой. Проверка зависимостей и поиск секретов отражают состояние на указанную дату; их нужно повторять перед релизами.

После установки обновления закройте старые вкладки/окна приложения и откройте заново. Старый клиент без X-Account-ID получает 428 при сохранении. Не удаляйте офлайн-хранилище с очередью: сначала сохраните копию и синхронизируйте её под исходным аккаунтом.

## Сервер

- Владельца снимка определяет только сессия. Каждый Telegram ID имеет отдельный snapshot; чужой ID в JSON не даёт доступ.
- Сессии — криптографически случайные секреты, в базе только SHA-256. Cookie HttpOnly/SameSite=Strict, в HTTPS также Secure и __Host-префикс. Выход отзывает сессию.
- Вход требует личного подтверждения боту, совпадения Telegram ID, секрета браузерной привязки, срока 5 минут и одноразового завершения. Неподтверждённый /start сессию не выдаёт.
- SQL параметризован, запись атомарная. Ревизии предотвращают устаревшее сохранение, ID операций — повторное применение при потерянном ответе.
- Проверяются Host, Origin изменяющих запросов и Content-Type; CORS не включён. Ограничены размеры запросов, число задач/проектов, запросы входа и SSE-подключения.
- Backend слушает только loopback. Nginx перезаписывает X-Real-IP, задаёт публичный домен и проксирует SSE без буферизации. SQLite/секреты находятся вне публичной папки.
- В systemd применены отдельный пользователь, UMask=0077, ProtectSystem, ProtectHome, PrivateTmp и ограниченная папка записи. База имеет права 600, каталог — 700.
- Ошибки API не возвращают stack trace, SQL, токен или путь базы. Токен не включается в HTML/JS и диагностические сетевые сообщения бота.

## Клиент

Markdown очищается rehype-sanitize в карточках, подробностях и preview редактора. Скрипты, iframe, event-атрибуты и javascript-ссылки не исполняются. Внешние изображения становятся ссылками, без автоматической сторонней загрузки. Ссылки используют noopener noreferrer.

Production CSP разрешает скрипты, соединения и worker только своего origin; inline-JavaScript и eval запрещены. Inline-стили оставлены для редактора. Dev-сборка с source maps предназначена только для localhost.

Service worker кеширует только публичную оболочку. `/api/`, сессии и ответы с задачами в Cache Storage не сохраняются. Черновики IndexedDB разделены по Telegram ID. При выходе кеш своего аккаунта удаляется; непустая очередь требует сначала синхронизации или явного разрешения конфликта.

## Импорт и скачивание файлов

JSON читается через File API в браузере, без выполнения содержимого. Новый шаблон принимает только объявленные поля; старые копии проходят перенос по списку разрешённых полей. Внутренние ID, дополнительные свойства и данные аккаунта из файла не используются для получения прав. Новые ID создаёт приложение, владелец серверной записи определяется сессией.

Проверяются размер файла, количество объектов, длины текстов, реальные календарные даты и допустимые статусы/приоритеты. Неверный файл не заменяет существующие данные. Предпросмотр использует тот же очищенный Markdown; внешние изображения автоматически не загружаются. После подтверждения сервер повторно проверяет итоговый снимок, в том числе его размер. Этот же лимит действует при создании задач ботом.

Экспорт JSON выполняется локально общей функцией downloadJson, без стороннего сервиса. Резервная копия содержит личные задачи и описания; её нужно хранить вне репозитория. Шаблоны docs/templates содержат только публичные примеры. Импорт не является восстановлением SQLite или сессии.

## Telegram

Обрабатываются только личные сообщения владельца чата и разрешённые callback. ID updates сохраняются; повтор update не создаёт повторную задачу. Настройки времени/часового пояса валидируются. Отправка по расписанию выключена у новых аккаунтов и включается самим пользователем.

Процесс использует только HTTPS Bot API. Токен должен находиться в `.env` либо защищённом EnvironmentFile, не в Git, URL интерфейса или localStorage. При компрометации токена отзовите его в BotFather и перезапустите службу; перед этим сохраните базу.

## Хранение и ограничения

localStorage/IndexedDB не зашифрованы и доступны владельцу профиля браузера и JavaScript этого origin. Не храните в задачах пароли и ключи. SQLite и резервные копии содержат личные данные всех аккаунтов и хеши действующих сессий; ограничивайте доступ и шифруйте внешние копии по своей политике.

Серверная авторизация не может отозвать уже доступную офлайн-копию до восстановления сети. Для общих компьютеров используйте выход до закрытия браузера. Смена аккаунта не открывает кеш прежнего ID через интерфейс, но не заменяет защиту профиля операционной системой.

Проверки изоляции и конфликтов не являются независимым пентестом. Нагрузочная проверка, защита от объёмной DDoS-атаки и аудит реальной конфигурации VPS в эту локальную проверку не входят. При публичной регистрации контролируйте размер базы и ресурсов сервера.

## Релизы и инфраструктура

release:prepare собирает точный отправленный коммит в временной папке, без .env и базы. Архив привязан к SHA; upload/install сверяют checksum и REVISION. Контрольная сумма защищает от повреждения, но не является подписью автора. Ключи SSH и доступ к GitHub/VPS остаются отдельной границей доверия.

Установщик делает копию SQLite, переключает ссылку current и проверяет backend; при неудачном запуске возвращает предыдущий код. Это не откат данных и не проверка всех функций. Скрипт не меняет Nginx, сертификаты, /etc/todo.env или чужие контейнеры. Проверка health подтверждает доступность процесса, а не правильность бота, HTTPS или изоляции в реальной инфраструктуре.

При внешнем порте 8443 Host передаётся через $http_host и должен совпадать с APP_ORIGIN. Порт 4001 остаётся loopback. Если 443 занят VPN, его нельзя освобождать остановкой контейнера без отдельного решения о переносе VPN.

## Повторение проверок

```sh
npm ci
npm audit
npm test
npm run test:e2e
npm run build
```

`tests/server.test.js` проверяет сессии, Telegram-вход, разделение данных, Origin, ревизии, идемпотентность, расписание и повтор updates. `tests/sync.test.js` — слияние/конфликты. `tests/remote.spec.js` — полный браузерный вход с имитацией Telegram, разные аккаунты, SSE, вкладки, офлайн-перезагрузку и восстановление связи. tests/import.test.js проверяет форматы, лимиты и все опубликованные шаблоны; tests/import.spec.js — подтверждение, отмену и повтор после ошибки записи. tests/release.test.js проверяет отказ при старом/повреждённом архиве и неподготовленном Git. Проверки Markdown/CSP и адаптивности сохранены.

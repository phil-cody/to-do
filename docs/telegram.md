# Telegram-бот

Имя приложения: `@just_to_do_it_bot`. Код бота находится в `server/telegram.js` и запускается вместе с backend. Нужен токен этого бота от BotFather. Токен задаётся только на VPS в `/etc/todo.env` либо локально в `.env`; в Git и чат его добавлять не нужно.

## Три функции

1. **Вход.** Кнопка на сайте выдаёт ссылку `/start login_<id>`. Бот показывает домен и кнопки подтверждения/отклонения. Подтверждение связано с Telegram ID и секретной cookie исходного браузера.
2. **Задачи на сегодня по расписанию.** Пользователь самостоятельно включает отправку и задаёт время и IANA-часовой пояс в приложении или командой `/remind`. Отправляются незавершённые задачи со сроком на текущую дату этого часового пояса. Если во «Входящих» есть незавершённые задачи, сводка также содержит их количество и список независимо от срока. Завершённые задачи исключены. Напоминание использует существующие время, часовой пояс, включение и отключение рассылки; пустой раздел не отправляется. Команда `/today` выдаёт ту же сводку.
3. **Новые задачи в Inbox.** Обычное текстовое сообщение в личный диалог создаёт задачу. Первая строка становится названием, остальные — Markdown-описанием. Статус Pending, приоритет Low, срок не задан. Длинная первая строка ограничивается 200 символами; исходный длинный однострочный текст сохраняется в описании.

Свойства аккаунта и сообщения связаны с числовым Telegram ID. Бот игнорирует группы, каналы, сообщения других ботов и неподходящие callback-запросы. Файлы и голосовые сообщения пока не преобразуются в задачи.

## Форма добавления задачи

Команда `/new` и кнопка «Добавить задачу по форме» в ответах на `/start` и `/help` открывают сайт по адресу `APP_ORIGIN/#new-task`. Порт из APP_ORIGIN сохраняется, включая 8443. При подключении бот регистрирует команды для меню личных чатов.

Открывается та же форма, что на сайте: название, Markdown-описание, проект, срок, статус и приоритет. По умолчанию выбран Inbox, но проект можно изменить. Задача создаётся только после сохранения; после него открывается выбранный проект.

Это обычная ссылка на сайт, без автоматического входа по Telegram ID. Если в браузере нет сессии, нужно подтвердить стандартный вход; после подтверждения форма откроется автоматически. Ссылка не содержит токенов или данных пользователя. Отмена формы не создаёт задачу. Обычные сообщения по-прежнему добавляют задачи в Inbox без формы.

## Команды

| Команда                        | Действие                                               |
| ------------------------------ | ------------------------------------------------------ |
| `/start`, `/help`              | Подсказка                                              |
| `/new`                         | Открыть полную форму создания задачи на сайте          |
| `/today`                       | Отправить список незавершённых задач на сегодня сейчас |
| `/remind 09:00 Europe/Moscow`  | Включить ежедневную отправку в указанном часовом поясе |
| `/stop`                        | Отключить ежедневную отправку                          |
| `/language`                    | Выбрать русский или английский кнопкой                 |
| `/language ru`, `/language en` | Сменить язык напрямую                                  |

Описания команд регистрирует само приложение через setMyCommands: общие варианты на двух языках и персональный вариант для выбранного языка аккаунта. Изменение языка ставит обновление меню в постоянную очередь; при доступном Telegram оно доставляется в очередном цикле, обычно в пределах 15 секунд. Изменения меню через BotFather могут быть перезаписаны приложением. Для выбранной схемы входа /setdomain не требуется: используется личный диалог и deep link, а не виджет Telegram Login. В .env нужен точный APP_ORIGIN сайта для cookie и защиты запросов.

Язык общий с сайтом: /language показывает две кнопки, /language ru и /language en меняют его без меню. Он применяется к новым ответам, подтверждениям входа, кнопкам и ежедневным спискам. Расписание и содержимое задач сохраняются. Сайт получает изменение через SSE или фоновый опрос; работающий офлайн клиент увидит его при восстановлении связи. Уже отправленные сообщения Telegram остаются на прежнем языке.

## Получение сообщений

Используется long polling `getUpdates`, поэтому публичный Telegram webhook не нужен. Входящий доступ Telegram к VPS на отдельный порт не открывается. Серверу нужен исходящий HTTPS-доступ к `api.telegram.org`.

Перед запуском проверяются `getMe` и отсутствие активного webhook. Если webhook уже установлен, отключите его через Bot API `deleteWebhook`, не выбирая удаление накопленных обновлений. Не вставляйте URL с токеном в общие журналы, скриншоты и историю команд. Другой poller для того же бота должен быть остановлен.

Смещение updates и ID обработанных сообщений сохраняются в SQLite. Повтор update не создаёт повторную задачу. Исходящие ответы сначала попадают в постоянную очередь; при временной ошибке отправка повторяется с задержкой. Форматирование исходящих сообщений — обычный текст, предпросмотр ссылок отключён.

Смена токена не сбрасывает обработанные updates: в рабочем режиме используется устойчивый ID самого бота. При недоступности Telegram backend продолжает обслуживать уже вошедшие аккаунты, а подключение бота повторяется в фоне. Новые входы доступны после успешного подключения.

## Расписание и доставка

В настройках аккаунта часовой пояс выбирается из списка городов с текущим смещением UTC. В начале доступны сохранённый пояс, пояс устройства и популярные города; далее — остальные пояса, поддерживаемые браузером. Выбранный ранее пояс сохраняется, даже если браузер использует другое название-синоним. Сезонные переходы учитываются по правилам выбранного пояса, время рассылки остаётся местным.

Планировщик проверяет время раз в 15 секунд. После заданного времени формируется один выпуск за день; если приложение перезапускалось, отправка за текущий день происходит после восстановления работы. Прошлые дни не догоняются. Отметка дня и сообщения очереди создаются в одной транзакции. Пустой список тоже даёт сообщение «нет незавершённых задач».

Длинный список разбивается на сообщения допустимого размера. Временные ошибки и ограничения Telegram приводят к повтору; блокировка бота пользователем отключает его расписание. При сбое между успешной доставкой Telegram и записью подтверждения в SQLite отдельное исходящее сообщение может повториться: Bot API не даёт ключа идемпотентности для sendMessage. Повторное создание задач при обработке входящих updates исключается транзакцией и уникальным ID update.

Вход в приложение сам по себе не включает рассылку. Её можно выключить в аккаунте или командой `/stop`. Выход из браузера не отключает добровольно включённое расписание бота.

## Локальная проверка

Автотесты используют имитацию Telegram и временные базы. Настоящий токен при них не нужен, сообщения реальным пользователям не отправляются. Для проверки настоящего бота настройте `.env`, запустите `npm run server`, затем пройдите вход, отправьте тестовую задачу и задайте своё расписание. Это отдельная проверка после установки токена.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api), [deep links](https://core.telegram.org/bots/features#deep-linking).

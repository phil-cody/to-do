# Импорт проекта с задачами

Проект можно заранее подготовить в JSON-файле и добавить в приложение целиком. Эта же форма принимает резервные копии Todo и переносит старые задачи из localStorage. Импорт доступен в локальном и серверном режимах; серверный импорт выполняется только в текущий аккаунт.

## Как подготовить и загрузить проект

1. На сайте нажмите «Импорт проектов и задач» → «Скачать шаблон проекта». В репозитории также есть [полный и минимальный шаблоны](templates/README.md).
2. Откройте JSON в текстовом редакторе. Измените название и описание проекта, заполните массив tasks. Элементы массива можно копировать, добавлять и удалять; пустой массив допустим.
3. Сохраните файл в UTF-8 с расширением .json. В JSON нельзя добавлять комментарии; строки заключаются в двойные кавычки. Перенос строки внутри описания записывается как `\n`.
4. В форме импорта выберите файл. Проверьте названия проектов, количество задач, сроки, статусы и приоритеты в предпросмотре.
5. Нажмите «Добавить проекты и задачи». До этого момента данные не меняются. После сохранения откроется общий список.

Минимальный пример можно взять из [minimal-project.json](templates/minimal-project.json); он содержит только обязательные поля. Не редактируйте format и version: это версия формата, а не название проекта. Пример без дополнительных полей:

```json
{
  "format": "just-to-do-it/project",
  "version": 1,
  "project": {
    "title": "Запуск сайта",
    "description": "## Цель\n\nОпубликовать **первую версию**.",
    "view": "kanban",
    "tasks": [
      {
        "title": "Подготовить макет",
        "description": "- [ ] Главная страница\n- [ ] Мобильная версия",
        "dueDate": "",
        "status": "pending",
        "priority": "high"
      }
    ]
  }
}
```

## Поля

| Поле                 | Значение                                                                |
| -------------------- | ----------------------------------------------------------------------- |
| project.title        | Обязательное название, до 200 символов                                  |
| project.description  | Markdown-описание, до 100000 символов; можно пропустить                 |
| project.view         | grid, list или kanban; по умолчанию grid                                |
| project.tasks        | Массив задач, в том числе пустой                                        |
| title у задачи       | Обязательное название, до 200 символов                                  |
| description у задачи | Markdown-описание, до 100000 символов; можно пропустить                 |
| dueDate              | Существующая дата ГГГГ-ММ-ДД либо пустая строка; по умолчанию без срока |
| status               | pending, in-process или completed; по умолчанию pending                 |
| priority             | low, medium или high; по умолчанию low                                  |

Overdue не задаётся вручную: он определяется по сроку незавершённой задачи. ID проекта и задач, даты создания и связь задач с проектом создаёт приложение. Неизвестное поле в шаблоне считается ошибкой, чтобы опечатка не приводила к потере значения.

## Перенос старых данных

Для переноса между localhost и VPS на прежнем адресе откройте «Импорт проектов и задач» → «Скачать текущие задачи», сохраните файл, затем откройте сайт на VPS, войдите в нужный аккаунт и загрузите JSON через ту же форму. Предварительно записывать файл в localStorage нового домена через Console больше не нужно.

Если старые задачи уже находятся в localStorage **текущего адреса**, откройте «Telegram и аккаунт» → «Перенести локальные задачи» → «Прочитать локальные задачи». Затем проверьте предпросмотр и подтвердите добавление. Браузер не может прочитать localStorage другого домена/порта — для него нужна копия файлом.

Принимается обычная резервная копия Todo с массивом projects. Исходный файл и localStorage не меняются. Старые внутренние ID не используются повторно. Задачи проекта с project_type=inbox добавляются в существующий Inbox; остальные проекты создаются заново.

## Повторный импорт и ошибки

Импорт добавляет данные и ничего не заменяет. Совпадающее название проекта получает суффикс «(импорт 2)», «(импорт 3)» и т. д. Новые проекты не закреплены и добавляются после существующих незакреплённых проектов. Повторное подтверждение того же файла создаёт копии; импорт не является обновлением ранее загруженного проекта.

Лимит файла JSON — 285 МиБ с учётом вложений. После добавления рабочая область должна укладываться в 300 проектов, 10000 задач, 2 МБ метаданных и 200 МиБ вложений. Каждый файл — до 20 МиБ, до 10 на задачу. Резервная копия включает байты файлов в base64; ссылки без содержимого не импортируются. Подробнее — [data.md](data.md). Общие ограничения определены в workspaceLimits, а проверка календарных дат — в isDueDate общей модели; сервер проверяет тот же предел размера снимка, в том числе для задач бота. Ошибки полей содержат номер проекта/задачи и поле. Если сохранение не удалось, предпросмотр остаётся доступен для повторной попытки, существующие данные сохраняются. В офлайн-режиме серверного аккаунта импорт попадает в обычную устойчивую очередь синхронизации.

В предпросмотре показываются первые 50 проектов и первые 20 задач каждого проекта с указанием оставшегося количества; подтверждение добавляет все проверенные данные. Длинный список прокручивается внутри предпросмотра.

Оба JSON-шаблона проверяются тем же парсером и серверным валидатором в tests/import.test.js; загрузка, отмена, ошибки сохранения и повторный импорт проверяются в tests/import.spec.js. Перенос localStorage в серверный аккаунт проверяется в tests/remote.spec.js.
